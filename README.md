# ギリギリサウナ ♨️

おじさんの希望温度に、ロウリュひとつで近づけろ。

サウナの管理人になって、ピクトグラムのおじさんが言う「今日は92℃がいいな」に合わせて、サウナストーンへ水を掛けて室温を調節する温度調節・記憶・感覚ゲームです。本番では温度計が最初の3秒しか見えません。

## 遊び方

1. おじさんが希望温度を言う（85〜110℃）。開始温度は65.0〜85.0℃のどこか。
2. **水ボタンを長押し**すると柄杓に水が溜まる（50ml/秒、最大100ml）。
3. **指を離す**と水がかかり、温度が上がる：**上昇量 = 水量(ml) × 0.15℃**
4. 温度は下げられず、自然に冷めることもない。上限は120℃。
5. ちょうどいいと思ったら「これで完成！」。

| モード | 内容 |
|---|---|
| 練習 | 温度計が常に見える。掛けるたびに上昇量も表示。ランキングなし。 |
| 本番 | 開始から3秒だけ温度計を表示（その間は水を掛けられない）。以降は温度情報が一切出ない。結果はXに投稿できる。 |

### 評価とスコア

`score = max(0, round(10000 − 誤差 × 1000))`

| 誤差 | 評価 |
|---|---|
| 0〜0.5℃ | 神のロウリュ |
| 0.5℃超〜1℃ | 天才熱波師 |
| 1℃超〜3℃ | プロサウナー |
| 3℃超〜5℃ | まあまあ |
| 5℃超〜10℃ | ぬるい／熱すぎ |
| 10℃超 | 出禁 |

### 操作

- タッチ／マウス：水ボタンを長押し → 離す。押したまま指がボタン外に出ても継続し、離した時点で掛けます。
- キーボード：水ボタンにフォーカスして Space / Enter を長押し。
- 操作がキャンセルされた場合（着信・ジェスチャー割り込み・タブ切替など）は「水をこぼした」扱いで温度は変わりません。
- 右上のスピーカーでミュート切替（設定は保存されます）。

## 開発環境

ビルド不要の素のHTML / CSS / JavaScript（ES Modules）。外部ライブラリ・外部画像・外部APIなし。描画はSVG、効果音はWeb Audio APIで合成しています。

```
.
├── index.html               # 画面構成（タイトル／遊び方／ゲーム／リザルト）とサウナ室のSVG
├── css/style.css            # レイアウト・演出（縦画面中心、レスポンシブ）
├── js/
│   ├── config.js            # 公開設定（共有URL・ハッシュタグ）
│   ├── logic.js             # 温度計算・判定・スコア・共有文（DOM非依存、練習／本番で共通）
│   ├── audio.js             # 効果音（ジュワァァ、ジングル等）
│   └── main.js              # 画面制御・入力・演出
├── tests/logic.test.mjs     # ロジックの単体テスト（node:test）
└── .github/workflows/deploy.yml  # テスト → GitHub Pages デプロイ
```

### 設計メモ

- **温度はセンチ度（0.01℃）の整数で保持**。上昇量は `水量 × 15` センチ度なので、何杯掛けても浮動小数点誤差がたまらず、スコアも `10000 − 誤差(センチ度) × 10` で厳密に計算されます。
- 練習・本番とも `applyWater()` だけで温度を更新します。違いは温度計を表示するかどうかのみ。
- 本番中の温度は画面ローカルのクロージャ内だけにあり、`window` やDOM（テキスト・属性・aria・デバッグ表示）には出しません。温度計は非表示ではなくDOMから取り除きます。汗・揺れ・セリフなどの演出も「掛けた水量」だけに基づき、現在温度を手がかりにできないようにしています。
- 画面ごとに AbortController／タイマー／アニメーションをまとめたスコープを作り、画面遷移時にすべて破棄します。

## 起動方法

ES Modules を使うため、`file://` ではなくローカルサーバーで開いてください。

```bash
# どれか1つ
npm start                    # npx serve（http://localhost:5173）
python3 -m http.server 5173  # Pythonがある場合
```

テスト：

```bash
npm test
```

## デプロイ（GitHub Pages）

1. GitHubで空のリポジトリを作成（例：`girigiri-sauna`）。
2. push する：
   ```bash
   git remote add origin https://github.com/<ユーザー名>/girigiri-sauna.git
   git push -u origin main
   ```
3. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。
4. `main` への push ごとに Actions がテスト → デプロイを実行。公開URLは `https://<ユーザー名>.github.io/girigiri-sauna/`。

### 共有URLの設定

`js/config.js` の `shareUrl` が空なら、今開いているページのURLをXの投稿に添えます。独自ドメインなどで固定したい場合だけ書き換えてください。

```js
window.GIRIGIRI_SAUNA_CONFIG = {
  shareUrl: 'https://example.com/girigiri-sauna/',
  hashtag: 'ギリギリサウナ',
};
```
